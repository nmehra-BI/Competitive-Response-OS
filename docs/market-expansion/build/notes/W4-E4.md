## Decisions

### E4-1 · Draft task editing is gated by `experiment.edit` on a set in force
- Context: D-113 lets the experiment owner and the case owner edit unsent validation tasks after G1.
- Decision: `tasks.addDraft/editDraft/removeDraft` authorize with case visibility (404) then `experiment.edit`
  in the case scope (the case-owner role; the experiment owner holds it too, as D-098 already requires for
  preview). The set must be an experiment set (`INVALID_TRANSITION` for a pilot set) whose experiment is still
  locked by the authorizing gate (`PRECONDITIONS_UNMET` otherwise). `TaskSet.draftEditable` reports the same
  rule for the viewer. Sponsor, reviewers and the pilot owner get 403; agents `AGENT_IDENTITY_FORBIDDEN`.
- Alternatives: allow the pilot owner (Jonas previews/sends validation tasks) — rejected, D-113 names only the
  experiment owner and case owner.
- Consequences: Jonas can still preview/send (unchanged), but not edit wording.

### E4-2 · "Unsent" means `not_sent` or `in_preview`; an edit resets the preview
- Decision: a task is a draft while its link is absent, `not_sent` or `in_preview` (the DB guard's rule). An
  edit of a previewed task sets its link back to `not_sent`; the send already refuses a preview whose content
  hash no longer matches (title, owner/assignee, due date, deliverable are in the hash), so what is written to
  the tool is always what was last previewed (never-rule 10 spirit). Removed tasks are filtered out of
  `loadTaskSet` (view, preview, send, CSV) and My Work; the row stays (audit + history). New ordinals follow
  every task including removed ones (unique `(task_set_id, ordinal)`).
- Audit: `task.created`, `task.updated` (field names only, never values), `task.removed`; no analytics event;
  no materiality (not material, D-113).

### E4-3 · Mapping check uses the connector's `preview()`; Not found from `problemCodes`
- Decision: `admin.checkMapping` previews one synthetic item per person (map keys ∪ owners of tasks in sets
  using the mapping); `assignee_not_found` / `assignee_not_in_project` → Not found; no account → Unmapped. No
  write in the tool or here (`audit: 'none'`). The simulated Postgres store has no membership table, so for the
  simulated provider the check treats an account with an active `permission_denied` fault rule as not a project
  member (the simulator's own way of refusing an assignee) and lets the connector's `preview()` report it. See
  CR-W4-E4-2.

### E4-4 · Material impact = dry run of `plan_destination_changed` over the plans the mapping serves
- Decision: affected = task sets with `mapping_id` = the mapping and ≥ 1 unsent, non-removed task. Their plan
  component (`pilot_plan_version`, or the experiment's original `experiment_plan_version`) is looked up in
  `snapshot_component` pins, evaluated with the tenant's active materiality policy (pure evaluator, nothing
  written), and turned into lines by the new pure `impactLines()` in domain materiality ("Approval G2 ·
  Snapshot v3 needs re-approval", "6 unsent tasks pause", "G2 · Snapshot v3 goes out of date · …", escalation
  copy for uncertain). Save of such a change without `acknowledgeMaterialImpact` → 409 `PRECONDITIONS_UNMET`
  with the lines as blockers; with it, `applyMateriality` runs in the same transaction. Assignee-only edits are
  never material. The replacing `admin.setMapping` also refuses a purpose change and unknown people, and never
  overwrites a row another tenant holds (insert `ON CONFLICT DO NOTHING` → 404).
- Consequence: a pilot plan version is pinned only at activation (pilot module), so before activation a
  destination change has no approval impact (nothing can be sent yet either). See CR-W4-E4-3.

### E4-5 · One-step "Accept as fact" — what "every citation opens" means
- Decision: at least one citation; each cited id resolves (passage → source, or source id) in the tenant; each
  source's chip is not restricted for the viewer (`sourceChips`: availability, deletion, licence entitlement —
  so E3's licence fail-closed rule applies automatically). The viewer must also hold `claim.accept_ai`.
  `oneStepAccept` is set on claim proposals only (absent for other types); reasons never name or count hidden
  sources. `acceptAsFact` writes `claim.created_from_proposal`, `claim.accepted` and `proposal.accepted` in one
  transaction; refused (400 `VALIDATION_FAILED`) with `editedPayload`, for `reject`, uncited, scenario/actual or
  an unopenable citation, before any write.

### E4-6 · Reachable pool is checked against SAM, not an input of it
- Decision: the sizing engine no longer lists `sizing.sam.population` as an input of `sizing.reachable_pool`;
  the pool node carries `checks: [{nodeKey: sizing.sam.value | sizing.sam.population, relation:
  checked_against, text: "upper-bound check: 500 ≤ 2,000 sites"}]` (`>` when breached; the engine blocks with
  `REACHABLE_EXCEEDS_SAM` then). `lineageView` returns `usedByEdges` (relation + detail) and `usedBy` includes
  checkers; `usedByTransitive` follows check edges ("SAM bounds the pool, which feeds SOM"). `lineage.get`
  returns `relation`/`detail`; the connected drawer renders "Reachable pool (upper-bound check: …)".
- Consequence: the reachable pool's `dependsOnAssumptionCount` now counts its own input only (honest).

### E4-9 · Connector calls carry the tenant (E5 request)
- `taskSync.preview` and `admin.checkMapping` build the connector from a `ConnectionRef` with `tenantId:
  ctx.tenantId` (typed `ConnectionRef & { tenantId }` so it compiles before E5's optional field lands). Jira
  credentials are row-level secured; harmless for the simulated connector. E5's branch was not merged here.

### E4-8 · Lineage drawer formula (coordinator bug)
- The drawer renders `label = expression`, and engine formula text already starts with its left-hand side, so
  SAM read "SAM = SAM = …". The connected `LineageDrawer` strips a plain leading `name = ` before rendering
  (`formulaExpression`), unit-tested.

## Workflow updates
- WF-07 (task sync): new draft step after G1 — edit/add/remove unsent validation tasks → preview → send. New

## Change requests
- **CR-W4-E4-1 · `Proposal.citations`** (contracts): the confirm dialog must show citations, but a proposal
  carries only passage/source ids, and `evidence.get` resolves source ids only; the dialog shows "Cited passage
  n · each opens for you". Proposal: additive `citations: SourceChip[]` (viewer-filtered, metadata only).
- **CR-W4-E4-2 · simulated project membership** (connectors/db `sim`): `createPgSimStore().projectMembers()`
  returns `[]`, so the real-stack simulator never reports Not found. Proposal: a `sim.project_member` table (or
  membership from the fault rules inside the store) so `problemCodes` come from the simulator itself; then
  remove the wrapper in `admin/mapping.ts` (`connectorFor`).
- **CR-W4-E4-3 · pin the pilot plan at G2** (gates, E3): the G2 snapshot pins `pilot_plan_version` only at
  activation; pinning at snapshot creation would let a destination change before activation stale/invalidate
  G2 as D-114 intends for any approved set.
- Data: aster-demo seeds no thesis for ME-104 (S05 shows "No thesis yet"); the E4 real spec creates a draft via
  `thesis.saveDraft` first. Consider a fixture thesis for aster-demo.
