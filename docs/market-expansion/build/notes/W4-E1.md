# W4-E1 — Data-entry editors A: S06 sizing editor, S08 economics editor (ticket 1, first half)

Stream E1 of `docs/market-expansion/build/WAVE4.md`. Decisions applied: D-112 §2–§3, D-132, D-030, D-033,
D-054, never-rules 3, 4, 5. Base `b1d540b`.

## Decisions

### E1-1 — A blank input is cleared, never saved as 0
- **Context:** D-112 says a blank stays Unknown. The contract has `clearInputKeys` on both saves.
- **Decision:** In both editors a blank value (or "Unknown — not entered" as the S06 basis) sends the key in
  `clearInputKeys`; the server deletes the draft row. Sizing then has no result (`MISSING_INPUT`, the ladder
  shows nothing, never zeros); economics either has no result (a required driver) or reports the optional one
  as "Not available — …" (one-time investment, downside, upside). A key set and cleared in one save is
  refused (400). The S06 ledger lists every editor input that is not entered as "Unknown · Not entered"
  (required ones add "blocks the snapshot"); `InputLedgerRow.kind` became nullable in `packages/ui` for it.
- **Alternatives:** keep a row with a null value (the column is `NOT NULL`; would need a migration); send 0
  (never-rule 5).
- **Consequences:** a cleared input disappears from the draft only; the committed version keeps its rows.

### E1-2 — Economics links are checked for unit and currency
- **Context:** `drivers[].assumptionId` lets the operator link any register assumption.
- **Decision:** a link takes the assumption's current value and must have the driver's unit (so a /year
  assumption can never become the one-time investment — never-rule 3) and, for money, the model's currency.
  `assumptionId: null` unlinks (draft value); omitting it keeps the old rule (same value keeps the link). A
  header currency change is refused while a linked money driver is in another currency.
- **Consequences:** `VALIDATION_FAILED` with codes `unit_mismatch`, `currency_mismatch`, `unknown_assumption`,
  `no_value`, `negative`.

### E1-3 — The opex scope note is stored with the exclusions text
- **Context:** WAVE4 E1 says `economics_version.exclusions_text` carries the rest; the engine's exclusions
  sentence is a constant and the export reads it from the engine output, so the column was only ever that
  constant. No response field carries an opex note.
- **Decision:** `exclusions_text` = engine sentence + `"\nOpex scope: <note>"`; the note comes back as the
  basis text of the "Annual incremental opex" ledger row, `"Scope: <note>"`, and the editor reads it there.
- **Alternatives:** a new column (migration, not ours); dropping the note (contract field accepted silently).
- **Consequences:** CR-W4-E1-2 asks for a proper field.

### E1-4 — Sizing basis text and boundary
- `inputs[].basisText` → `sizing_input.basis_text`; absent keeps the old text, null clears it; it is copied
  into a new draft and frozen at commit. The ledger shows it before the register's basis (the reachable pool's
  channel definition reads first). Product boundary and the four "includes" flags make a new immutable
  `market_boundary` row when they change; the first save uses them (product falls back to the mandate's
  product name only when absent). `dedupRuleText` and `overlaps[].method` are stored as given.
  `sizing.compareVersions` now also lists product boundary and dedup rule changes.

### E1-5 — Editors autosave through the shared draft hook; the S06 save may take two requests
- Both editors use `lib/drafts.ts` `useDraft` (debounce 800 ms, flush on blur, If-Match, conflict = "Take
  theirs / Keep mine"). S06 sends only what changed against the last server state; cohorts are sent as a
  whole list with ids by position; an overlap between two cohorts created in the same save is sent in a second
  request once the server has given them ids. The first S06 save is not sent until market unit, currency and
  reference year are valid ("Define the market boundary first …").
- S08 gained "Start the economics model" (no economics yet; `If-Match: 0`, drivers from the register and the
  committed sizing, the existing server rule) and "Edit drivers in draft vN" (only a snapshot exists). Before
  this the screen could not edit a case whose economics had no draft (the real aster-demo state).
- "Create snapshot vN" in the S06 editor flushes first and is disabled with its reason while inputs are missing
  or checks block. The S08 snapshot button also allows a first version (no snapshot to compare with).

### E1-6 — The one-time investment has its own block
- The S08 drivers table holds only /year and rate drivers (price, adoption per scenario, margin, opex,
  capacity, reachable pool). "One-time scale-entry investment" (`MONEY_MEASURE_LABELS`) is a separate dashed
  block under the table with its own link; the money cards keep the "Do not add" divider; cash flow and
  payback stay "Not available".

### E1-7 — Each editor queues its own saves
- **Context:** in the full real suite two sizing PATCHes ran at once and the second hit the unique
  `(sizing_version_id, input_key)` row (409). `lib/drafts.ts` lets a blur `flush()` and the debounced save both
  wait on the same in-flight save and then both start (not an E1 file).
- **Decision:** both editors chain their `save` calls; each one plans its patch against the state the previous
  save left and uses that state's row version, so the duplicate is empty and sends nothing.
- **Follow-up for the owner of `lib/drafts.ts`:** let only one waiter proceed after an in-flight save (other
  screens on the hook have the same race).

### E1-8 — The economics link select is named "Assumption link"
- Its options read `ASM-09 · 60%`. Naming it after the driver ("Gross margin · assumption") made
  `getByLabel('Adoption by year 3 · Base')` ambiguous for existing specs, and option text with assumption names
  repeated money labels of the cards (`€400k one-time`).

## Change requests

- **CR-W4-E1-1 — `me.economics_driver.source_id`.** `economics.saveDraft` accepts `drivers[].sourceId`
  (D-132) but no column holds it (0001 has `assumption_id` / `assumption_version_id` only; 0006 adds
  nothing). The handler refuses a non-null `sourceId` with `VALIDATION_FAILED · source_link_unsupported`
  ("Link the driver to an assumption; the assumption carries its evidence") rather than drop it. Proposal:
  `0007`: `ALTER TABLE me.economics_driver ADD COLUMN source_id uuid REFERENCES platform.source(id)`; then the
  driver ledger row reads kind `evidence` with its source chip and the editor's link list adds sources.
- **CR-W4-E1-2 — `EconomicsVersion.opexScopeNote: string | null`** (additive) so the note is not carried in
  `exclusions_text` and the ledger basis text (E1-3).
- **CR-W4-E1-3 — draft checks when a draft cannot calculate.** `SizingVersion.result` is null when inputs
  are missing, so the view carries no `MISSING_INPUT` check; the editor recomputes the missing list from the
  ledger. An additive `SizingView.draftChecks: CalcCheck[]` (and the same on `EconomicsView`) would let
  every screen show the server's own message.
- **Gap (not a CR for E1):** `cases.createDirect` has no S01 form; the E1 real spec creates the case through
  the API (WAVE4 E1 names `createDirect`). An operator cannot start a direct case in the UI yet.
