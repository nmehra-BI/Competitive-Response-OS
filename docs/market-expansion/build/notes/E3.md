## Decisions

### E3-1 · Routing by the matrix: sponsor, committee or authority gap
- Context: D-109 §1 gives a default matrix (sponsor and committee ceilings per gate) and per-person grants; the
  brief says "route a request by the matrix (authority row + the viewer's grant)".
- Decision: `routeRequest()` (domain, `platform/policy/governance.ts`) routes a request to the **sponsor** when
  the amount is within min(matrix sponsor ceiling, the case sponsor's own valid grant) and, for X, the parent
  G2 + every other live extension of it + this one ≤ the sponsor's G2 grant; else to the **committee** when
  within the matrix committee ceiling; else **authority gap**. G0 always routes to the sponsor (no spend); G3
  never does (sponsor ceiling null). A placeholder amount routes like the smallest ask and stays unapprovable.
  `GateRequest.route` and `ApprovalPanelState.route` carry it.
- Alternatives: route by the viewer's grant (two viewers would see two routes for one request); route by the
  matrix only (a sponsor without a grant would be "routed" to themselves).
- Consequences: a €200k G2 or an X that breaks the cumulative rule goes to the committee. On the sponsor route
  only the sponsor or another holder of authority for the gate may decide (a committee member without a G2
  grant cannot return Elena's G2); on an authority gap nobody can approve (FORBIDDEN-free: AUTHORITY_INSUFFICIENT
  "… Authority gap").

### E3-2 · Committee quorum: seats on the current snapshot, decisions recorded per seat
- Decision: on the committee route a decider must hold a live seat in the gate's BU (`committee_member`);
  the approval row records `committee_seat` (server-assigned; a seat in the body is ignored). The request moves
  only when `evaluateCommittee()` says so: **approved** when ≥ quorum seats approved on the current snapshot and
  every required seat is among them (approved-with-conditions when any of those approvals carries conditions);
  **not approved** when quorum can no longer be reached (a required seat records Not approved, abstains, is
  excluded or vacant, or too few seats remain); otherwise the request stays Awaiting decision and the audit
  action is `gate_request.committee_decision_recorded` (no `gate_approved` until quorum). A return for revision
  by any seat returns the request at once. Quorum = the policy's `requiredApprovals` when the policy names its
  seats (G3: 2), else the D-109 default 2 of 3 with the finance seat (a G1/G2/X above the sponsor ceiling).
- Lapse (never-rule 2): only approvals on the current snapshot count; earlier ones show as `lapsed` and are not
  invalidated rows (nothing was ever authorized by them). One decision per seat per snapshot (the existing
  `approval_one_per_seat_idx`) and per person per snapshot (existing unique index).
- Exclusions (D-109 §3): package author and case owner (SELF_APPROVAL_PROHIBITED, existing guard); the finance
  reviewer who signed this case's economics review (CONFLICT_OF_INTEREST, via the policy's conflicted list —
  applied on the committee route only, so Daniel stays FORBIDDEN on Elena's sponsor-routed G2).
- Status texts: "Waiting on 2 of 3 approvers · finance seat required", "Waiting on second approver · finance
  seat", "Waiting on the finance seat", "Quorum reached · 3 of 3 with the finance seat", "Quorum cannot be
  reached · finance seat did not approve | abstained | excluded (conflict)".

### E3-3 · Expiry from the gate policy
- Decision: `expires_at` = decision + `approvalExpiryDays` when the effective policy's `approvalExpires` is true

### E3-4 · Extension rule enforced at request and at decision
- Decision: `outcomes.requestExtension` checks `checkExtensionRequest()` before anything is written: ≤ 25% of the
  parent's approved amount (rounded down to cents), ≤ 50% of the parent window and ≥ 14 days, ≤ the parent's
  sites, no scope line that adds sites or prospect outreach (negated lines such as "No prospect outreach" pass),
  re-tested thresholds unmet or inconclusive (default: every parent target whose latest result is not Met),
  one extension per parent (withdrawn and Not approved ones do not count). Outside the rule → 400
  VALIDATION_FAILED with the rule's sentence ("The extension asks €31k; the rule allows up to €30k (25% of
  €120k)."); a second X → 409 INVALID_TRANSITION. A null cap or duration in a real tenant → 400 "State the
  extension cap and duration"; an illustrative tenant keeps the €[cap] placeholder (submittable, never
  approvable). The same rule is the X precondition `extension_within_rule` / `one_extension_per_parent`
  (pre-approved keys, added to `ME_GATES.X` and the Aster X policy).
- The X request stores `windowStart/End`, `maxSites` and `retestTargetIds` in its scope; "What this does not
  authorize" adds "No prospect outreach". `OutcomeReviewView.extensionLimits` = the S12 limits text.

### E3-5 · Stop rules and measure types on the G2 request
- Decision: `gates.createRequest` assigns ids and keys SR1…n to `stopRules`, stores them in the request scope
  (every G2 created now stores the key, even when empty), and freezes them into the first G2 snapshot
  (`SnapshotContent.stopRules`, readable lines added to `budgetAndStopRules`: "SR2 · … → Recommend stop · owner
  Jonas Klein"); refresh copies the previous snapshot's rules. `budget_and_stop_rules` needs ≥ 1 structured
  rule on a request that carries the key (a request stored before D-122 keeps its text rules). A threshold rule
  must watch one of the request's thresholds. Every G2 threshold needs a `measureType` (400 otherwise); it is
  stored on `outcome_target.measure_type`, copied on refresh, written into the snapshot's `outcomeTargets`
  (first G2 snapshot now lists the G2 thresholds, not an empty list) and loaded into the G3 facts.

### E3-7 · Licences fail closed in reads; expiry job; live provider gate
- Reads: `evidence.get` (and `accessBySource`, used by search and export) caps an `excerpt` entitlement to
  `aggregate_only` when the licence is not confirmed in writing, has ended, or allows 0 sentences — no
  passage, quoted fact or count leaves the API. `SourceDetail.license` carries rights status, term and action.
- `timers.license_expiry` (daily 02:15): a licence expires the tenant-local day after `term_ends_on`; one UPDATE
  drops it to metadata only and sets `expired_at` (the DB constraint forbids anything else); for
  `delete_copy_keep_audit` the licence's sources get `deleted_at`; passages and provenance rows stay (FK from
  claims); audit `license.expired` (system). A renewal in S14 (new confirmation, term not ended) clears
  `expired_at`.
- Live analysis: `admin.setLiveAnalysis` refuses "on" without the addendum reference/date and an eval run
  reference/time (400; the DB check refuses too). The worker wraps a live provider with `gateLiveProvider()`:
  each provider call first reads `tenant_ai_setting`; when off it returns a provider `refused` error without
  calling the provider, so the harness stops "Stopped — your work is saved" with the business reason. The
  fixture provider is never wrapped.

### E3-8 · Authority grants: DoA reference and 12-month default
- `admin.setAuthority` requires `doaReference` for a new or re-activated grant (kept on edits); a new grant
  without `validTo` gets validFrom + 12 months − 1 day. `admin.authority` gap copy is unchanged ("No G3 approver
  in BU Water · Authority gap" — step 29); "Committee named · G3 authority not granted" is an `admin.committee`
  gap and is shown next to the G3 gap in S14.

### E3-9 · Committee membership administration
- `admin.setCommitteeMember`: human only (API AGENT_IDENTITY_FORBIDDEN + DB guard), never the acting admin

  DoA reference required, a revoked seat stays revoked (name the holder again with a new id). Audited
  `admin.committee_member_named | _changed | _revoked`.
